# 60/30/10 Color Rebalance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebalance the main site's color tokens/usage to a true 60/30/10 read — dark navy dominant, dark-gray secondary surface, orange as the single sparingly-used accent — per `docs/superpowers/specs/2026-08-04-60-30-10-color-rework-design.md`.

**Architecture:** Pure CSS token/usage changes across 4 existing files (`root.css`, `cards.css`, `buttons.css`, `header.css`). No HTML changes, no new files, no build config changes.

**Tech Stack:** Static site built with minimaz-cli. No test framework — verification is `npm run build`, `npx minimaz validate --path=<file>`, targeted `grep` checks, and a manual visual pass via `npm run start`.

## Global Constraints

- Scope is main-site files only: `root.css`, `header.css`, `hero.css`, `buttons.css`, `cards.css`, `tiles.css`, `footer.css`, `bottom-bar.css`, `form.css`, `prefers.css`. Do not touch `legal.css` or `referral.css` — they intentionally keep separate palettes.
- `--clr-accent`'s hex value is not changed, only where it's used (link hover/focus only from here on).
- The scrollbar thumb (`::-webkit-scrollbar-thumb`) stays orange — out of scope, do not touch.
- Every task must end with `npm run build` succeeding and `npx minimaz validate --path=<changed file>` passing before commit.
- Never commit unless the task step explicitly says to (per repo owner's standing instruction) — these plan steps do include explicit commit steps; do not add extra commits beyond what's listed.

### Task 3: Restyle `.btn.secondary` as a neutral outline button

**Files:**
- Modify: `src/styles/buttons.css`

**Interfaces:**
- Consumes: `--clr-border`, `--clr-text-main`, `--clr-primary` (all already declared in `root.css`).
- Produces: `.btn.secondary` no longer references `var(--clr-accent)` or `var(--clr-accent-hover)` anywhere. The base `.btn .icon` rule (`color: var(--clr-primary)`) is left untouched and now applies to secondary buttons' icons too (icons are small enough to stay accent-colored per the spec).

- [ ] **Step 1: Replace the secondary button rules**

In `src/styles/buttons.css`, find this whole block:

```css
/* ------------------------------
   SECONDARY BUTTON (BLUE)
------------------------------ */
.btn.secondary {
  background-color: var(--clr-accent);
  border-color: var(--clr-accent);
  color: #ffffff;
}

.btn.secondary .icon {
  color: #ffffff;
}

.btn.secondary:not([aria-disabled="true"]):hover {
  background-color: var(--clr-accent-hover);
  border-color: var(--clr-accent-hover);
  color: #ffffff;
  box-shadow: 0 4px 16px rgba(0, 102, 153, 0.35);
}
```

Replace it with:

```css
/* ------------------------------
   SECONDARY BUTTON (NEUTRAL OUTLINE)
------------------------------ */
.btn.secondary {
  background-color: transparent;
  border-color: var(--clr-border);
  color: var(--clr-text-main);
}

.btn.secondary:not([aria-disabled="true"]):hover {
  background-color: transparent;
  border-color: var(--clr-primary);
  color: var(--clr-primary);
  box-shadow: none;
}
```

Note: the old `.btn.secondary .icon { color: #ffffff; }` rule is intentionally deleted, not kept — without it, secondary button icons fall back to the base `.btn .icon { color: var(--clr-primary); }` rule already defined earlier in this same file, which is correct per the spec (small icon glyphs stay accent-colored).

- [ ] **Step 2: Verify no blue remains on secondary buttons**

Run: `grep -n "clr-accent" src/styles/buttons.css`
Expected: no output (zero matches).

- [ ] **Step 3: Build and validate**

Run:
```bash
npm run build
npx minimaz validate --path=src/styles/buttons.css
```
Expected: build succeeds, validation prints `SUCCESS`.

- [ ] **Step 4: Commit**

```bash
git add src/styles/buttons.css
git commit -m "style: restyle .btn.secondary as neutral outline instead of blue fill"
```
